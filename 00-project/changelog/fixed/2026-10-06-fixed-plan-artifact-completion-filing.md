## Summary

- Adopted the plan-artifact completion filing lifecycle from the T3 plan [`plans-completed/implementation/2026-10-06-plan-artifact-completion-filing-proposal-261006-1504-gpt6sol.md`](../../plans-completed/implementation/2026-10-06-plan-artifact-completion-filing-proposal-261006-1504-gpt6sol.md). Generated/finalised plans now carry a proportional **artifact lifecycle inventory** and exactly one gate-owned terminal filing task plus its paired filing Success Criterion, excluded only from implementation-entry eligibility (never pre-ticked; only the gate ticks them after verified filing effects). The terminal gate (`04-documentation/03-mark-completed.md`) now files and verifies the completed **package** with a split two-fact report: `Implementation verification: VERIFIED/NOT VERIFIED` and `Package filing: PENDING/BLOCKED/PARTIAL/VERIFIED`; blocked or partial filing is never labeled COMPLETED. No automatic move engine, no new closure-with-deferred mode, no manifest parser, no zip bundles.
- Fixed four workflow defects (symptoms and root cause in the paired troubleshooting entry):
  1. **Missing artifact handoff** — execution/confirmation handed off with no associated-artifact inventory, so research, review archives and evidence had no lifecycle link and the gate archived only the plan file.
  2. **Late state check** — Phase 4 archived the plan in step 3 before the step 7 `check-plan.sh --state` run that was supposed to happen "before the plan is archived", and the Reconcile-only mode row omitted step 7. Steps now run 1,2,4,5,6,7 before the deferred filing step 3; the Reconcile-only table includes step 7.
  3. **Unresolved-policy completion marker** — an unresolved host archive policy blocked only the move yet still applied the completion marker, hiding "implementation verified; filing pending/blocked". The split report now separates the two facts and leaves filing boxes unchecked.
  4. **Scoped archive exclusion** — the active-link checker always skipped `00-project/plans-completed/` with no deliberate way to verify a filed package.
- Guards: `scripts/validation/check-active-markdown-links.sh` gained `--root <repository-root>` and repeatable `--scope <file-or-directory>` (explicit scopes override the default archive skip, stay within the selected root, and fail closed on missing/unreadable/escaping scopes, symlink escapes, empty scopes and scope cycles; default scan behavior unchanged and the escaped-root allowlist remains empty), covered by a 31-case CLI selftest (`check-active-markdown-links-selftest.sh`) plus the legacy built-in `--self-test` invocation. New `check-artifact-lifecycle-policy.sh` plus its selftest (29 negative mutations checked against a passing live-copy baseline) guard the lifecycle contract in the template and workflows, and `check-artifact-filing-selftest.sh` rehearses the terminal filing end to end across S1–S5 plus the S2b modeled-rollback branch — a fixture-state model driving the real lint/link CLIs, not prose execution (S5 proves the scoped link check detects the wrong-path move that lint alone passes).
- Key behaviors now proven by the adopted docs and guards (independent-oracle review R1–R6): legacy plans receive a minimal artifact inventory and filing pair upfront, without a tier bump; the final lint runs on the **actual current plan path**, including partial-attempt paths; a failed final-path verification rolls back the `✅ COMPLETED` marker and resets only the filing pair, preserving every non-filing mark, and revalidation never blindly resets recorded `VERIFIED`/`BLOCKED`/`PARTIAL` reasons; external debt keeps scoped eligibility (open debt stays open in plan and tracker without blocking verified tasks); premature local ticks of the gate-owned filing pair are guarded; and the CLI fails closed on empty scopes and scope cycles.
- Enabling link hygiene, scoped small so the repository-wide link gate can actually pass: repaired the moved-proposal inbound link in [`docs/2026-10-06-docs-plan-artifact-completion-filing-proposal.md`](../docs/2026-10-06-docs-plan-artifact-completion-filing-proposal.md) (`research/` → `plans/`, historical research outcome preserved; the owner re-updates it on archive), and converted the escaped-root hyperlink in [`docs/2026-10-03-docs-setup-subagent-limit.md`](../docs/2026-10-03-docs-setup-subagent-limit.md) into an explicitly external code-form locator that preserves its Update-AI-Tools provenance. No allowlist weakening.
